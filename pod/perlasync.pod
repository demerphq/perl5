=encoding utf8

=head1 NAME

perlasync - cooperative resumable execution in Perl

=head1 DESCRIPTION

This document describes the experimental iterator interface.  An iterator
allows a block of Perl code to suspend at an explicit C<iterator_yield> and later
continue from that point.  Iterators are cooperative: calling the iterator
is what advances it, and no thread, event loop, or implicit scheduling is
provided.

The interface is experimental and may change or be removed in a future Perl
release.

=head1 ITERATORS

Enable the feature before using the C<iterator_create> and C<iterator_yield> keywords:

    use feature 'iterator';

    my $counter = iterator_create {
        iterator_yield 1;
        iterator_yield 2;
    };

The C<iterator_create> expression returns a callable iterator.  Calling it
runs the body until the next C<iterator_yield> or until the body finishes:

    my @first  = $counter->(); # (1)
    my @second = $counter->(); # (2)
    my @done   = $counter->(); # ()

Each C<iterator_yield> produces exactly one list element.  In scalar context the yielded
value is returned as the scalar result of the call.  C<undef> is a yielded
value, not an empty result:

    my $values = iterator_create { iterator_yield undef };
    my @value = $values->(); # one element, whose value is undef

The body runs in the context of the call that resumes it.  Lexical variables,
loop state, and localization in the body remain in effect across an
C<iterator_yield> and are restored when the iterator finishes.  The iterator
does not accept arguments.

=head1 LIFETIME AND ERRORS

When the body finishes without another C<iterator_yield>, the completing call
returns an empty list and the iterator becomes exhausted.  Exhaustion is permanent: a
later call raises an exception.  An iterator is also permanently failed if an
uncaught exception leaves its body.  That exception is propagated by the call
which resumes the iterator, and later calls raise an invalid-resume
exception.  An exception caught by an C<eval> inside the body does not by
itself terminate the iterator.

The C<iterator_exhausted> keyword tests completion without resuming the iterator:

    iterator_exhausted $counter

It returns true only after a resume has run the body to completion and
returned an empty list.  It returns false while the iterator is new or
suspended, and also for a failed iterator.  Testing exhaustion does not
advance the sequence.

An iterator cannot be resumed while it is already running.  This includes an
iterator attempting to call itself before it has reached an
C<iterator_yield>.  A suspended
iterator is a one-shot continuation; it is not copied when it is assigned or
passed around, so all references designate the same continuation.

=head1 WHERE C<iterator_yield> MAY BE USED

C<iterator_yield> is valid only lexically inside an C<iterator_create> block.
It is not valid in an ordinary subroutine or in callback code such as C<sort>, C<map>,
C<grep>, or a regular-expression code block.  Callback code cannot suspend
the operation that invoked it.

=head1 SEE ALSO

L<perlfunc/iterator_create BLOCK> describes the C<iterator_create> keyword in
the Perl function reference.  L<perlembed> and L<perlinterp> describe other forms of
embedding and interpreter execution; they do not provide iterator scheduling.
